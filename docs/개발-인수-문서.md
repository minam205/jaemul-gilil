# 로또 사기 좋은 날 — 개발 인수 문서

2026-11-11 기준 · 기획 담당 이영호(leeyh@zkrypto.com) · 저장소 https://github.com/minam205/jaemul-gilil

이 문서 하나로 서비스를 이어받을 수 있게 썼습니다. 코드는 `index.html` 한 파일(약 69KB)에 전부 들어 있습니다. 빌드 도구, 서버, 데이터베이스가 없습니다.

옛 이름은 "재물 길일 나침반", "로또택일"입니다. 저장소 이름(`jaemul-gilil`)과 저장 키(`jaemul…`)에 흔적이 남아 있습니다.

---

## 1. 서비스 정의

| 항목 | 내용 |
|---|---|
| 하는 일 | 생년월일시로 사주를 세워, 이번 회차 로또를 **어느 요일에, 어느 방향 판매점에서** 사면 좋은지 알려 준다. 산 날은 60갑자 도장첩에 모인다. |
| 타겟 | 사주와 미신을 좋아하는 60~70대 로또 구매자. 한자를 모르는 사람도 포함한다. |
| 이름 | 로또 사기 좋은 날. 휴대폰 홈 화면 아이콘 밑 짧은 이름은 "로또 좋은 날"(잘리면 "로또 사기…"로 보이는 것을 막으려고 따로 둠). |
| 부제 | 내 사주로 고른 날과 판매점 방향 |
| 약속하지 않는 것 | 당첨, 확률, 예측. 화면과 공유 문구 어디에도 쓰지 않는다. |
| 요금 | 무료. 광고와 결제 없음. |

### 깨면 안 되는 전제
모든 기능은 **본인이, 그날, 그 방향으로, 직접** 사는 것을 전제로 한다. 대리 구매를 부탁하게 하거나 날짜와 방향을 건너뛰게 하는 기능은 넣지 않는다. 구매 수량을 지시하는 문구("한 장이면 충분")도 쓰지 않는다. 절제 안내는 "지나치다 싶으면 한국도박문제예방치유원 ☎1336" 한 줄로 한다.

## 3. 화면과 흐름

```
입력 → 회차 목록 → 날짜 상세 → 길일 도장첩
```

화면은 `show(view)` 하나로 전환한다(`hidden` 토글). 주소 해시는 `#input #week #day #record`.

| 화면 | 들어 있는 것 |
|---|---|
| 입력 | 머리 문구(30종 중 무작위, `HOOKS` 배열), 설명, 안심 문구(무료, 생년월일이 휴대폰 밖으로 안 나감, 19세 이상), 처음 온 사람에게만 보이는 **예시 카드**(1960-03-15생 가상 인물의 실제 계산 결과), 년·월·일 고르기, 시진 고르기("모름" 포함), 이름, "내 길일 보기" 버튼, 접힌 "자세한 설정"(야자시, 30분 보정). 한 번 입력하면 다음부터는 이 화면을 건너뛴다. |
| 회차 목록 | 제목 "○○회 로또, 어느 날 살까"와 "내 생년월일" 버튼, 회차 선택(지난 회차~12회 뒤), 추첨 카운트다운, **답 카드**("○○회, 당신의 날은 ○월 ○일 ○요일입니다"), 추첨이 끝난 회차의 결과 묻기 카드, 일~토 7줄(요일, 날짜, 간지, 띠, 한 줄 설명, 등급 인장과 점수), 내 사주 요약, 도장첩과 달력 버튼, 설치 버튼, 하단 안내 |
| 날짜 상세 | 날짜와 등급 인장, 할 일 또는 피할 일, 황금 윤도 나침반과 방향 카드 4장, 그 방향 로또 판매점 찾기, 점수가 나온 까닭, "이날 샀어요", "자녀에게 부탁하기", "달력에 넣기", 전날·다음날 |
| 길일 도장첩 | 모은 도장 수와 칭호, 60갑자 도장판, "도장첩 자랑하기"(그림 공유), 산 날과 결과 목록, 도장첩 옮기기(저장 글자), 기록 지우기 |

### 날짜 규칙
- 한 주는 **로또 주기**다. 일요일에 시작해 토요일 추첨으로 끝난다.
- 회차 번호는 1회 추첨일(2002-12-07)부터 센다: `roundOf(일요일의 율리우스일)`.
- 토요일 20:00 이후는 판매 마감으로 본다. 답 카드는 남은 날 가운데 점수가 가장 높은 길 이상인 날을 고르고, 없으면 "이 회차엔 당신의 날이 남아 있지 않습니다"와 다음 좋은 날을 보여 준다.
- 추첨 시각(토 20:35)이 지나면 그 회차에 "샀어요"를 누른 기록에 대해 결과(꽝, 5등, 4등, 3등 이상)를 묻는다.

## 4. 계산 규칙

### 4-1. 사주 세우기 `saju(y,m,d,hh,mm,solar,yaja)`
- 날짜를 율리우스일로 바꾼다(`jdn`). 일진 번호는 `(J+49) mod 60`이고 0이 갑자다.
- 년주와 월주는 절기 기준이다. 태양 황경을 Meeus 저정밀식(`sunLon`)으로 구해, 입춘(315°) 전이면 전년으로 보고 월지는 30° 단위로 정한다. 외부 만세력 API를 쓰지 않는다. 절기 시각 오차는 몇 분 수준이다.
- `solar` 옵션은 서울 경도 보정(−30분), `yaja` 옵션은 23시 이후 출생을 당일 일주로 본다(야자시). 둘 다 기본으로 켜져 있다.
- 시진은 12지지 가운데 고른다. "모름"은 12:00으로 계산한다.
- 신강·신약은 간이 판정이다. 일간과 같은 오행, 일간을 낳는 오행이 전체 7점(월지는 2점) 가운데 45% 미만이면 신약, 55% 이상이면 신강이다.
- 맞춰 본 사례: 2000-01-01은 무오일, 1984년 입춘 전후로 년주와 월주가 바뀜, 1979-11-18 23:55(야자시)는 기미년 을해월 기축일 병자시.

### 4-2. 날짜 점수 `scoreDay(me, J)`
로또는 횡재로 보고, 월급 같은 정재보다 편재를 높게 쳤다.

| 규칙 | 점수 |
|---|---|
| 일진 천간이 내 편재(재성이면서 음양이 같음) | +4 |
| 일진 천간이 내 정재 | +1.5 |
| 일진 지지의 주된 기운이 편재 / 정재 | +4 / +1.5 |
| 천을귀인 지지 | +2 |
| 천간합(갑기, 을경, 병신, 정임, 무계) | +2 |
| 일지와 육합 / 삼합 | +2 / +1.5 |
| 역마(일지 삼합국 기준) | +1.5 |
| 일지 충 / 년지 충 | −3 / −2 |
| 공망(일주가 속한 순의 공망) | −2 |
| 편관(일간을 극하고 음양이 같음) | −1.5 |
| 신약이면 재성 점수에 0.6을 곱하고, 비겁·인성 천간 날에 +1 | 조정 |

등급은 4점 이상 대길, 2점 이상 길, −2점 초과 평, 그 밖은 흉이다. **규칙 자체는 명리학의 전통 개념이지만 점수 숫자는 이 앱이 정한 값이다.**

### 4-3. 방향
- 그날 로또 사러 갈 쪽(재신방)은 일진 천간으로 정한다: 갑을 동북, 병정 서남, 무기 북, 경신 동, 임계 남.
- 사람 만날 쪽(희신방): 갑기 동북, 을경 서북, 병신 서남, 정임 남, 무계 동남.
- 늘 유리한 쪽은 내 재성 오행의 방위다: 목 동, 화 남, 토 중앙, 금 서, 수 북.
- 윤도 그림은 `drawCompass()`가 SVG로 그린다. 안쪽부터 팔괘(후천), 24방위, 24절기, 72분금 눈금이다. 금색 쐐기가 그날 갈 쪽(±22.5°), 초록 테두리가 늘 유리한 쪽, 주황 구슬이 사람 만날 쪽이다. 절기 고리를 24방위와 같은 각도에 맞춘 것은 단순화다.

## 5. 판매점 찾기 (카카오)
- 버튼을 누를 때만 SDK를 불러온다(`loadKakao`). 키는 `index.html`의 `KAKAO_KEY`다.
- 이 키는 카카오 개발자 콘솔 **"입지 분석 스코어맵" 앱**의 JavaScript 키다. 카카오는 계정당 한 앱에만 지도 무료 할당을 주기 때문에 기존 앱의 키를 같이 쓴다. Web 도메인에 `https://minam205.github.io`가 등록되어 있다. 다른 도메인에서 돌리려면 콘솔에 도메인을 추가하거나 자기 키로 바꿔야 한다.
- 검색 중심을 **그날 방향으로 1km 옮긴 지점**에 둔다. 내 위치를 중심으로 하면 가게가 많은 동네에서 가까운 45곳이 반경 300m 안에서 다 차서 그 방향 가게를 못 받아 온다.
- 옮긴 지점 반경 1.4km에서 "로또"와 "복권"을 각각 3쪽(최대 45곳)씩, 내 위치 반경 800m에서 "로또"를 한 번 더 찾아 합친다. 거리는 내 위치 기준으로 다시 계산하고 2.5km 안만 남긴다.
- 방위각이 그날 방향 ±22.5° 안이면 "그 방향 판매점"(가까운 순 5곳), 아니면 "방향은 다르지만 가까운 곳"(2곳)으로 보여 준다. 길찾기는 카카오맵 링크다.
- 위치 권한을 거부하면 동네 이름을 넣어 찾는다(주소 검색, 실패하면 키워드 검색).

## 6. 공유, 달력, 도장첩

| 기능 | 동작 |
|---|---|
| 자녀에게 부탁하기 | 공유창을 띄운다(`navigator.share`, 없으면 복사). 글은 "○월 ○일에 로또 가게 좀 같이 가 줄래? 내 사주로 보니 그날이 내 길일이고, 내가 있는 데서 ○쪽 가게로 가야 한대. (찾은 판매점 이름과 주소) 사고 올게. 너도 네 길일 봐 봐: 링크". **대신 사다 달라는 글이 아니라 같이 가 달라는 글이다.** |
| 달력에 넣기 | `.ics` 파일을 내려받게 한다. 종일 일정이고 5시간 전 알림이 붙는다. 서버 알림이 없어서 휴대폰 달력에 맡긴 것이다. |
| 이날 샀어요 | 기록을 저장하고 화면 가운데에 붉은 도장이 찍히는 연출을 보여 준다. 다시 누르면 취소한다. |
| 도장판 | 산 날의 일진(60가지)마다 한 칸이다. 먹색은 산 날, 금테는 대길에 산 날, 붉은 "당첨"은 5등 이상이다. 같은 일진은 더 좋은 기록으로 덮는다. 칭호는 10개, 30개, 60개에서 바뀐다. |
| 도장첩 자랑하기 | 캔버스(1080×1800)에 도장판을 그려 그림 파일로 공유한다. |
| 도장첩 옮기기 | "저장 글자"를 공유창으로 내보내고, 붙여 넣어 되살린다(7절). |

## 7. 저장 데이터

| 키 | 내용 |
|---|---|
| `jaemul2` | 생년월일시 `{y, m, d, h(시진 번호), n(이름), so(30분 보정), ya(야자시)}` |
| `jaemul_rec` | 구매 기록 `{ [율리우스일]: {J, bought, score, grade, dir, gi(일진 번호), result(none·r5·r4·r3·null), at} }` |
| `jaemul` | 옛 형식(날짜·시각 문자열). 읽기만 하고 `jaemul2`로 옮긴다. |

저장 글자 형식은 `JAEMUL1.` 뒤에 base64로 감싼 JSON `{v:1, birth, rec}`이다. 되살릴 때 기존 기록과 합치고, 같은 날이 겹치면 `at`이 더 늦은 쪽을 둔다.

저장은 기기와 브라우저마다 따로다. 브라우저의 사이트 데이터를 지우거나 휴대폰을 바꾸면 사라진다. 아이폰은 홈 화면 앱을 지우면 같이 지워진다.

## 8. 화면과 문구 규칙

타겟에 맞춰 여러 번 고친 끝에 정한 것이다. 새 화면과 문구도 여기에 맞춘다.

### 화면
- 본문 20px, 버튼 높이 60px, 한지색 바탕에 먹색 글자 한 가지 테마(다크모드 없음).
- 헤더는 고정하지 않는다. 내용과 같이 스크롤된다.
- 등급은 한글 인장(대길, 길, 평, 흉)에 점수를 같이 쓴다. 한자만 쓰는 표기는 금지다.
- 이모지를 쓰지 않는다.
- 조작은 누르기 하나다. 밀기나 끌기 동작을 요구하지 않는다.

### 문구
- 사주 글자(지지, 십신)를 화면 앞에 두지 않는다. 달력 날짜, 방향, 할 일로 바꿔서 보여 준다. 간지(신사일)는 보여도 된다. 이 세대에게는 신뢰의 근거다.
- 방향은 기준점(지금 있는 곳), 각도, 확인하는 법(휴대폰 나침반, 해 뜨는 쪽이 동쪽), 그쪽에 가게가 없을 때의 대안을 한 묶음으로 쓴다.
- 한 줄에 정보 하나를 쓴다. 가운뎃점으로 서로 다른 정보를 잇지 않는다. 주어와 동사가 있는 문장으로 쓴다.
- 외래어를 쓰지 않는다(캘린더는 달력, 기기는 휴대폰).
- 나이를 부르지 않는다(어르신, 시니어, 실버).
- 당첨, 1등, 확률, 예측을 말하지 않는다.
- 머리 문구는 꿈을 인정하고, 내 것으로 만들고, 오늘 할 일을 말하는 순서다. 예: "같은 5천 원이면, 내 사주에 돈 들어오는 날에 사세요."

### 버린 시도
가챠(뽑기) 연출 버전을 만들었다가 버렸다. 결과가 사주 계산으로 정해져 있어 뽑기의 불확실성이 없고, 두 번째부터는 연출이 답까지 가는 장애물이 된다고 판단했다. 그 가운데 추첨 카운트다운, 도장 찍는 연출, 수집(도장첩)만 남겼다.

## 10. 알려진 한계

1. **음력 입력이 없다.** 타겟은 음력 생일로 기억하는 사람이 많다. 한국천문연구원 음양력 정보(공공데이터포털)를 붙여야 한다. 가장 먼저 할 일이다.
2. 신강·신약이 간이 판정이라 재성 반영률(100% 또는 60%)이 전문 감정과 달라질 수 있다.
3. 23시대 출생자는 야자시 옵션에 따라 일주가 바뀌고 길일이 통째로 달라진다.
4. 머리 문구 30종 가운데 어느 것이 잘 먹히는지 측정하지 않는다. 서버가 없어서다.
5. 달력 파일은 한 번 더 확인을 눌러야 들어간다. 타겟이 혼자 하기 어렵다.
6. 도장은 기기 안에만 있다. 60개를 모으는 데 1년 반이 걸리는데 휴대폰을 바꾸면 사라진다. 저장 글자는 임시 대책이다.
7. 윤도 그림의 글자 60여 개에 SVG 필터를 썼다. 오래된 휴대폰에서 상세 화면이 조금 느릴 수 있다.
8. 아이콘에 로또를 떠올릴 요소가 없다(팔괘 윤도 그림만 있다).
9. 카카오 키가 코드에 그대로 들어 있다. 도메인 제한으로 막고 있다.

## 12. 개발 방법

```
git clone https://github.com/minam205/jaemul-gilil
cd jaemul-gilil && python3 -m http.server 8080
```

- 의존성이 없다. `http://localhost:8080`에서 열린다.
- 판매점 찾기는 카카오 도메인 제한 때문에 localhost에서 안 된다. 콘솔에 `http://localhost:8080`을 추가하면 된다.
- 고친 뒤 `sw.js`의 `CACHE` 이름을 하나 올리고 `main`에 push한다. 이름을 안 올리면 설치된 앱이 옛 파일을 계속 쓴다.
- 계산 함수(`jdn`, `sunLon`, `saju`, `scoreDay`)는 화면과 떨어져 있어서 스크립트 앞부분만 잘라 Node에서 돌려 볼 수 있다. 자동 테스트는 없다.
- 권한: GitHub 저장소와 카카오 콘솔 모두 소유자(minam205, 이영호)에게 협업자 초대를 요청한다.
